# GraphiScan implementation plan

Updated 2026-09-29. This is the work order for the agreed [system flow](SYSTEM_FLOW.md) and [panel actions](PANEL_COMPLIANCE.md). Source edits are not proof that a feature works on a device or deployed server.

| Order | Work | Done when |
| --- | --- | --- |
| 1. Admin clarity | Audit every admin screen, remove repeated content and unsupported AI/clinical language, show classification and expert review clearly. Align the current Vue mobile result/progress copy with it. | Result/progress wording, dashboard repetition, list-table width, metric card consistency, and redundant Settings guidance were cleaned. Both Vue builds pass. Admin Dashboard, Users, Students, Results, Progress, Audit Logs, and Settings were visually inspected with synthetic data at desktop width; teacher results were inspected at 390px. Real authenticated browser flows, detailed record pages, and a physical phone still need review. **In progress.** |
| 2. Data and access foundation | Get a fresh schema/data export; migrate to Supabase PostgreSQL/Auth/private Storage; add school, Grade 1–3, account gates, permissions, and model/version fields. | Admin issued temporary credentials, first-login password change, approved agreement acceptance, school/student ownership, and private images are enforced by the API. |
| 3. Native mobile foundation | Start Expo/React Native with native navigation, typography, authentication gates, and a shared API client as soon as the data/access contract is stable. Rebuild the teacher flow first, then expert, parent, and guest. | A release build runs the core flow on a physical Android device; the Vue/Capacitor wrapper is no longer the mobile release target. |
| 4. Admin and mobile workflows | Connect account issuance, school and student management, reports, audit logs, and expert validation to the new API. Finish the same teacher, expert, parent, and guest flows in Expo. Retire or align old Flask pages. | Admin and native app actions use the same records and server-enforced role/ownership rules. |
| 5. Models and screening | Evaluate ResNet, EfficientNet, and MobileNet on one documented three-class split; integrate the validated default and model choice. Make Initial/Follow-up assignment transactional. | Results record class scores, model/version, report type, and expert status. No automatic advice is generated. |
| 6. Evidence and release | Align manuscript/diagrams with implemented behavior, review accessibility and responsive UI, measure nonfunctional requirements, then deploy. | Panel items are supported by actual system and manuscript evidence. Deploy only after secrets, storage, and access are reviewed. |

Start with admin clarity because the current result vocabulary is misleading. Implement the access and data foundation before connecting new admin functions or mobile screens; both clients must follow the same API contract. Start the Expo shell and teacher workflow as soon as that contract is stable, then complete the remaining roles while backend features are added. The current Vue/Capacitor app stays usable as a reference until Expo reaches parity; avoid further cosmetic investment in the wrapper. Free hosting choices and limits are in [STACK_DECISION.md](STACK_DECISION.md).
